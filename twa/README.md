# TWA (Trusted Web Activity) Setup

Convert your Solana PWA into an Android app using TWA. This allows your PWA to be distributed through the Solana dApp Store and run as a native-like Android app.

## Prerequisites

- Node.js 20+
- Java JDK 17+ (for keytool and gradle)
- Android SDK (optional - Bubblewrap can install it)

## Quick Start

### 1. Initialize TWA (First Time Setup)

```bash
cd twa
./scripts/init-twa.sh
```

This interactive script will:
- Prompt for your app configuration (name, package ID, host URL)
- Generate a signing keystore
- Extract SHA256 fingerprint
- Create `twa-manifest.json` from your input
- Update `assetlinks.json` with your package ID and fingerprint
- Build the signed APK

### 2. Deploy Your PWA

Your PWA must be deployed with the updated `assetlinks.json`. Verify it's accessible at:

```
https://your-app.vercel.app/.well-known/assetlinks.json
```

### 3. Test the APK

```bash
adb install app-release-signed.apk
```

### 4. Subsequent Builds

For future builds after initialization:

```bash
./scripts/build-twa.sh
```

## Scripts

| Script | Purpose |
|--------|---------|
| `scripts/init-twa.sh` | First-time setup: creates config, keystore, and builds APK |
| `scripts/build-twa.sh` | Rebuild APK (after init) |
| `scripts/update-assetlinks.sh` | Update fingerprint in assetlinks.json |

## Files

| File | Purpose |
|------|---------|
| `twa-manifest.template.json` | Reference template for configuration |
| `twa-manifest.json` | Generated by init script (gitignored) |
| `android.keystore` | Generated signing key (gitignored - keep secure!) |
| `CustomLauncherActivity.java` | Optional customization for TWA launch |
| `../public/.well-known/assetlinks.json` | Digital Asset Links for your domain |

## URL Bar Issue

If your TWA shows a URL bar instead of running fullscreen, Digital Asset Links verification failed. Check:

1. **assetlinks.json is deployed** - Must be accessible at `https://your-domain/.well-known/assetlinks.json`

2. **Fingerprint matches** - The SHA256 fingerprint must match your signing keystore:
   ```bash
   ./scripts/update-assetlinks.sh
   ```

3. **Package name matches** - The `package_name` in assetlinks.json must match `packageId` in twa-manifest.json (the init script ensures this automatically)

4. **Verify with Google's tool**:
   https://developers.google.com/digital-asset-links/tools/generator

## Updating Your App

When you need to release an update:

1. Update `appVersionCode` and `appVersionName` in `twa-manifest.json`
2. Run `./scripts/build-twa.sh`
3. Submit the new APK

## Chrome Preference

The `android-browser-helper` library automatically prefers Chrome for TWAs when it's installed - no custom configuration needed.

The `CustomLauncherActivity.java` is included for optional customizations like:
- Custom URL handling via `getLaunchingUrl()`
- Adding query parameters to the launch URL
- Custom splash screen behavior

Chrome is required for Mobile Wallet Adapter (MWA) to work properly on Android.

## Keystore Security

Your `android.keystore` file is critical:
- **Never commit to git** (it's in `.gitignore`)
- **Back it up securely** - You need the same keystore for all updates
- **Remember your password** - Cannot be recovered if lost

## Submitting to Solana dApp Store

1. Run `./scripts/init-twa.sh` (or `build-twa.sh` for updates)
2. Deploy your PWA with the updated `assetlinks.json`
3. Follow the [dApp Publishing Guide](https://github.com/solana-mobile/dapp-publishing)
4. Submit your APK and metadata

## Troubleshooting

### Build fails with "twa-manifest.json not found"
Run the init script first:
```bash
./scripts/init-twa.sh
```

### Build fails with "keystore not found"
Run the init script to create a new keystore:
```bash
./scripts/init-twa.sh
```

### Build fails with gradle errors
- Ensure JAVA_HOME is set to JDK 11+
- Try cleaning: `rm -rf app build .gradle && ./scripts/build-twa.sh`

### URL bar shows in app
1. Run `./scripts/update-assetlinks.sh`
2. Redeploy your PWA with updated assetlinks.json
3. Clear Chrome data on test device
4. Wait a few minutes for caching to clear

### MWA not working
- Ensure Chrome is installed on device
- Check Chrome version (83+ required for TWA)
